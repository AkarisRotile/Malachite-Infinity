# 可成长的孔雀翎 · Mod 开发工作流（Agent 执行版）

> 版本：v1.1（2026-09-02）· 接入《开源参考与合规规范》 ｜ 适用：本工作区（E:\孔雀翎）所有 mod 开发会话
> 本文档是**我（Agent）给自己写的可执行操作手册**：每次接手本项目的 mod 任务，先读本文档与
> `写法\当前状态与交接总览.md`，按阶段 A→G 执行；配套自动化门禁脚本：
> `写法\_tools\Mod-Gate.ps1`（真实可运行，见 §5）。

## 0. 工作区铁律（红线，全硬性）

| # | 规则 | 违背后果 |
|---|---|---|
| R1 | **只写工作区** `E:\孔雀翎`。ModSources 同步、游戏内构建/打包 `.tmod` 由作者执行；打包写用户 Mods 被拒（TML001）属预期，**不重试、不绕过** | 越权写入 |
| R2 | 编译通过 = 门禁脚本（§5）给出 PASS；`error CS` ≠ 0 一律不得宣称"编译通过" | 假验收 |
| R3 | 新增/改名/删除 ModItem / ModProjectile 类 → **存档旧物品失效**。改动前必须确认获取方式并**向用户声明存档影响**（历史教训：MalachiteItem → PeacockWillowBlade 改名后旧档物品作废，需重新砍树） | 存档不兼容 |
| R4 | 每个新用户可见文本（物品/弹幕/配置/对话/UI）必须进 `Localization\en-US_Mods.可成长的孔雀翎.hjson`（双语内联写法）；**禁止代码里硬编码显示文案** | 本地化缺失 |
| R5 | 颜色只允许 `Core\MalachitePalette.cs`；禁止散落 `new Color(数值)`（`UI\MalachiteUI.cs` 存量 ~60 处为已知债，阶段 2 一并收敛） | 风格失控 |
| R6 | 粒子特效一律走 `EffectLimiterSystem` 限流；弹幕/世界绘制**禁止 `TextureAssets.MagicPixel`**（1x1 用 `AdditiveLayer.Pixel`）；UI/HUD 条状填充可用但须确认是 UI 像素坐标系（StealthHUDBar / MalachiteUI 现用点由门禁 WARN 复核）；禁止巨型程序化光带方案（教训：首测超巨型光带/过曝） | 画面灾难 |
| R7 | `using CalamityMod` = 0；灾厄接触只允许 `Core\CalamityCompat.cs`（反射软引用），其余文件不得出现编译期灾厄类型 | 依赖回潮 |
| R8 | 参考/复用外部开源代码前**必读** `写法\开源参考与合规规范.md`（Wiki 协议≠代码协议；CalamityModPublic=专有·仅参考/借须署名 Azafure, LLC、CWR=MIT、CalamityEntropy=社区开源）；文件头补「代码来源与合规署名」（模板见 §4.5）；不搬运源码与贴图资产 | 合规事故 |
| R9 | 每次较大改动后：`写法\更新日志.md` 追加条目（模板 §6.2）；会话结束前更新 `写法\当前状态与交接总览.md` | 交接断链 |

> 需要专业依据时先加载 skill：美术/配色/像素 → `game-art-guide`；代码审查/重构决策 →
> `code-quality-workflow`；涉及 SillyTavern 才用 Tavern 系 skill（本项目不用）。

## 1. 阶段 A：上下文接管（新会话必做，约 5 分钟）

1. `pwd` 确认位于 `E:\孔雀翎`；扫一眼 `写法\` 与 `mod本体\可成长的孔雀翎\` 目录是否有新文件（作者可能自行补了东西）。
2. **按序必读**：
   1. `写法\当前状态与交接总览.md`（最浓缩的现状 + 下一步入口）
   2. `写法\更新日志.md` 尾部 3~5 条（最近改了什么、踩过什么坑）
   3. 本文件（本文档）
   4. 涉灾厄解绑/架构话题 → `写法\脱离灾厄方案.md`；涉外部代码参考/复用 → `写法\开源参考与合规规范.md`
3. **跑基线门禁**（首次必跑，确认环境可用 + 拿到基线）：
   ```
   pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1
   ```
   记录基线：`error CS = 0`；TML001 打包越界 = 预期；警告为已知清单（CS0618 LabelAttribute 过时等）。
4. 明确**当前主任务**（默认从总览「七、下一步建议」进入，例如：阶段 2 天赋重构设计）。

## 2. 阶段 B：需求分解 + 决策门（动手写码前，与用户对齐）

一个需求拆成一份**决策清单**，先给用户看、拍板后再动代码（历史模式：D1~D5 决策记录，都先对齐再实施）：

| 决策项 | 要问清的问题 |
|---|---|
| 目标与验收 | 这次做完，用户怎么算"成了"？（可玩/可测/视觉达标？） |
| 阶段归属 | 属阶段 0 隔离 / 1 自建武器 / 2 天赋重构 / 3 收尾 / 特效与美术迭代？ |
| 影响范围 | 预期动哪些文件？新增 vs 修改 vs 删除？（删除类=存档警告 R3） |
| 数值与曲线 | 基础伤害/攻速/潜伏阈值/技能点获取…是否本次定？还是沿用临时基线？ |
| 存档兼容 | 类名/键名变更影响旧档物品、Boss 击杀记录（MalachiteProgress 键：`Mod名:类型名`/`Vanilla:数字ID`）？ |
| 贴图归属 | 用户自绘 / 程序占位（用户后替换同名 PNG）/ 复用现成？ |
| 本地化 | 新增哪些 key？中英文案谁定？ |
| 合规 | 参考哪个仓库？对应许可级别（参考/改写/复用源码）？按 `写法\开源参考与合规规范.md` 定署名方式与文件头 |
| 性能 | 新增粒子量级？走不走 EffectLimiterSystem？ |

**大改动的纪律**：先在聊天里给用户一段"设计小段"（含影响面与取舍），编号记 D 决策；
用户拍板后才进入 C 阶段。任务若在中途被牵引扩张（新点子涌现），**先暂停，回到本条对齐，禁止自行无限扩散**。

## 3. 阶段 C：改动影响分析（写码前静态走查）

对着决策清单逐项走查，输出"影响清单"（短任务可口头过，长任务写进更新日志条目）：

- [ ] 新增/改名/删除的类 → ModItem/ModProjectile/ModSystem ID 变化 → 存档影响？
- [ ] 贴图引用路径：`Texture => "可成长的孔雀翎/Textures/xxx"`，新增贴图先确认尺寸与像素风（参考原版/灾厄 Malachite 翡翠多色带视觉语言）
- [ ] 调色板：需要新色 → 加进 `MalachitePalette`（同色系按 HSL 明度阶梯，改 L 不改 H），不得就地造色
- [ ] 本地化 key 清单（DisplayName/Tooltip/Label…）
- [ ] 伤害语义：是否用 `MalachiteDamageClass`（通用全继承 + 职业 25%）？有无职业联动检查（拳套攻速/召唤饰品位）
- [ ] 灾厄软引用：只允许门禁白名单四处——`Core\CalamityCompat.cs`（反射层）、`Core\MalachiteData.cs`（Cache TryFind 中枢）、`Items\PeacockModifier.cs`（旧灾厄武器服务）、`Players\MalachitePlayer.cs`（Draedon 探测等）；白名单之外出现灾厄字符串会被门禁 WARN，新增探测点先确认是否需要扩白名单
- [ ] 参考来源：对照 `写法\开源参考与合规规范.md` 定许可级别与署名方式——CalamityModPublic（Azafure LLC 专有·仅参考/借码须署名并附链接）、CalamityOverhaul（MIT·复用须保留版权声明）、CalamityEntropy（社区开源·复用建议进 Credits）
- [ ] 双轨兼容：本模组武器（孔雀柳刃）与旧灾厄武器（灾厄孔雀翎）是否都受本次影响？家族识别统一走 `MalachiteCache.IsMalachiteItem`

## 4. 阶段 D：实施规范

### 4.1 目录职责
| 目录/文件 | 职责 |
|---|---|
| `Items\` | ModItem 武器与词缀（PeacockWillowBlade 自建武器、PeacockModifier 服务旧灾厄武器） |
| `Projectiles\` | ModProjectile：MalachiteProj(飞刀)/MalachiteBolt(潜伏射线)/Orbiting(剑阵)/Domain(领域)/MalachiteProjectiles(旧接管类) |
| `Core\` | 系统层：隔离(Compat/Progress/Stealth)、数据(Cache/Data/Progress)、天赋、粒子限流、调色板、绘制辅助、伤害类 |
| `Players\` | MalachitePlayer：持有识别/潜伏值/天赋钩子/对话 |
| `World\` | 掉落、Boss 击杀记录（MalachiteGlobalNPC.OnKill） |
| `UI\` | MalachiteUI（星图/对话，存量色值债待收敛） |
| `Localization\` | en-US hjson（双语内联） |
| `Textures\` | 全部 PNG（武器原画 384x384 66° 倾角等；弹幕占位同名可替换） |

### 4.2 代码风格
- 命名空间统一 `可成长的孔雀翎`；文件名 = 主类名；一个文件一个主题；注释中文。
- tModLoader 2026（TML_2026_07）签名注意：ModItem hooks 多为 **无 Item 参数** 签名
  （`ModifyWeaponDamage(Player, ref StatModifier)` / `Shoot(Player,…)` / `UseSpeedMultiplier(Player)`）。
- 弹幕性能范式：`extraUpdates` 提速 + Dust 光尘拖尾（引擎级尺寸控制，杜绝巨型光带）；
  发光 = `AdditiveLayer` additive 混合；所有特效走 `EffectLimiterSystem`。

### 4.3 存档/键名约定
- Boss 击杀键：`可成长的孔雀翎:类名` 或 `Vanilla:数字ID`（见 MalachiteProgress）。
- 进度判定用 `ProgressSystem.GetStage()`；天赋解锁条件一律走 ProgressSystem/本地存档，不得直接读灾厄静态字段。

### 4.4 本地化写法
```hjson
Items: {
    NewItem: {
        DisplayName: 中文 / English
        Tooltip: 中文说明
    }
}
```
新增 key 后跑一次门禁（审计不查 hjson 完整性，靠 §8 DoD 清单人工核对：凡新增 class/配置/对话必须同步 key）。

### 4.5 合规署名头模板（规范全文见 `写法\开源参考与合规规范.md`）
参考型文件（文件最顶部，先于 using）：
```csharp
// 代码来源与合规署名：
// - <X 思路>参考自：<仓库名>（<许可>，<版权人>）—— <具体文件/目录>
//   <仓库链接>
// 本文件为自主实现，未直接复制上述仓库源码。
```
纯自主新文件：头部加一行 `// 本文件为自主实现，无外部参考代码。`
新增参考来源仓库 → 同步补 `description.txt` Credits 区。

各仓库署名与复用级别（速查）：
- **CalamityModPublic**（Azafure, LLC 专有许可）：仅"参考（Reference）"级别；提取/借用（Lift）代码片段必须在文件头署名 Azafure, LLC + 仓库链接；禁止重新打包/二次分发灾厄本体。
- **CalamityOverhaul（CWR）**（MIT）：可自由参考/修改/复用；复用源码须保留原作者版权声明与 MIT 文本。
- **CalamityEntropy**（社区开源）：接口/机制可参考；复用核心实现建议进 description Credits。

生成约束：
- 架构模板优先取 **CWR 或社区通用开源范式**；
- 重写/复用 **CalamityModPublic 特有逻辑**时，生成文件头部必加版权注释与来源署名。

## 5. 阶段 E：门禁（可执行、可复现）

### 5.1 运行门禁（每次改动后、宣称完成前必跑）
```
pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1        # Gate：编译 + 审计
pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1 -Mode Compile   # 只看编译
pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1 -Mode Audit     # 只看结构
```
> Windows PowerShell 5.1 下等价命令：`powershell -NoProfile -ExecutionPolicy Bypass -File .\写法\_tools\Mod-Gate.ps1`（脚本存为 UTF-8 BOM，5.1 与 PowerShell 7 均可直接运行）。
等价的原始命令（脚本内部就是它）：
```
dotnet build -c Debug --no-restore .\mod本体\可成长的孔雀翎\可成长的孔雀翎.csproj
```

### 5.2 通过标准
| 项 | 标准 |
|---|---|
| error CS | **0**（硬性） |
| 弹幕目录 MagicPixel、`using CalamityMod`、Palette 外新增数值色值 | 0（硬性，见 §0 R5/R6/R7） |
| TML001 打包越界 | 允许（预期，作者游戏内构建） |
| 编译警告 | 只允许已知清单（CS0618 LabelAttribute 存量；魔法数字建议），**新增警告类型需说明或修掉** |
| 产物 | `bin\Debug\net8.0\可成长的孔雀翎.dll` 已更新 |

### 5.3 常见失败处置
- `error CS*` → 修到 0 再跑。
- TML001/MSB3073（Access denied 写用户 Mods）→ 预期；不重试打包，交接给作者。
- MSB4236（还原缺失）→ 脚本自动换完整 restore 重试；仍失败再人工 `dotnet restore`。
- 审计 WARN（署名头缺失等）→ 逐条判读，新参考文件必须补头，纯自主文件注明即可。

## 7. 阶段 G：游戏内验证闭环（作者侧执行，Agent 配合）

工作区环境无法写入用户 Mods（R1），游戏内实测由作者完成；Agent 负责**把可测性与回归口径准备好**：

1. **提测自检**（Agent 侧，写进交接）：
   - [ ] 门禁 PASS；更新日志条目完整
   - [ ] 给出"测什么/怎么测"清单：获取途径（砍树掉落？）→ 手持表现 → 射击/潜伏 → UI 入口 → 存档影响（旧档/新档）
   - [ ] 新档旧档分别说明（例如：新武器需重新砍树获取）
2. **反馈→修复循环**（历史节奏：首测→根因→修复→二测）：
   - 复现问题 → 对照最近改动找根因（案例：巨型光带=内部纹理失控→Dust；"贴图没变"=新武器需重获取，非 bug）
   - 最小修复 → 门禁回归 → 更新日志追加"测试反馈修复"条目
3. **验收口径**：用户确认视觉/手感/数值达标才算本任务闭环；未闭环不留"假装完成"。

## 9. 命令速查

| 操作 | 命令（工作区根目录下） |
|---|---|
| 门禁全量 | `pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1` |
| 仅编译 | `pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1 -Mode Compile` |
| 仅审计 | `pwsh -NoProfile -File .\写法\_tools\Mod-Gate.ps1 -Mode Audit` |
| 裸编译 | `dotnet build -c Debug --no-restore .\mod本体\可成长的孔雀翎\可成长的孔雀翎.csproj` |
| 还原依赖 | `dotnet restore .\mod本体\可成长的孔雀翎\可成长的孔雀翎.csproj` |
| 定位编译器错误 | `dotnet build -c Debug --no-restore ... 2>&1 | Select-String 'error CS'` |

> 门禁脚本退出码：0 = PASS；1 = 硬性失败。TML001 打包越界不算失败（脚本已识别）。
