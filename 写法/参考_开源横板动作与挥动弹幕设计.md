## 二、关键认知：「大型 mod 的挥动不是挥动，是特殊的弹幕」

### 认知要点（对齐大模组实际做法）
- 挥动在引擎层面**没有物理**：不存在"拿着武器做手臂动画"。本质是生成一个"武器位"实体（held projectile），
  每一帧由一条 **时间→(角度, 刃长, 位置) 曲线** 摆出姿势——这就是一个**外观特殊的弹幕**。
- 命中 = 该弹幕在**若干活动帧**里移动的判定盒（AABB），或干脆按帧采样做扫过判定；与视觉是两回事。
- 视觉 = 在**同一条曲线**上采样的多层 VFX：本体贴图 / 弧光带(刀光) / 残影拖尾 / 前缘高亮 / 命中火花/闪光。
  玩家看到的"挥"其实是 VFX 层叠出来的结果，本体贴图只是舞台布景之一。
- 手感 = 曲线形状（爆发-过冲-回坐/蓄势-定格）+ 判定窗口 + 命中反馈（震屏/顿帧/白闪）+ 音效时机，
  与"物理挥动"无关。

### 落到本项目（MalachiteMelee / MeleeSlashProj）
- 已具备：爆发过冲→回坐曲线、蓄势/挥扫/定格状态、贴图残影+曳光细带、切线火花、覆盖全刃的大判定盒。
- 可再对齐的缺口（照参考游戏/大模组）：
  1. **活动判定窗口**：伤害只在挥扫中段的 20%~90% 时间窗激活（灾厄 DD 的做法），蓄势与收尾不判定，
     配合音效时机更"准"；当前实现是蓄势后全程判定。
  2. **命中反馈**：命中瞬间轻震屏（本地）+ 命中目标短暂白闪/命中闪光帧 + 音效分层；
     目前只有切线火花，缺"这一刀砍中了"的强反馈。
  3. **曲线 LUT**：把爆发曲线预算成查表（帧→角度/刃长），视觉/判定/音效用同一张表，便于整体换手感形状。
  4. **VFX 主次**：贴图本体只是布景，真正的"挥"由弧光带+残影+前缘亮线提供——调参时优先调这些层。
