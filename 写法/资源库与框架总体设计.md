## 一、背景与立项动机

| 事实 | 结论 |
|---|---|
| Terraria 侧的「Forge」**已经存在 = tModLoader**（Steam 官方 DLC、唯一 loader、Hook/注册体系齐备，仓库 MIT + 反编译原版源码受 TERMS_OF_USE 约束） | 不另起 loader；不 fork tML（除非未来明确要改 loader 本身，M 级决策另行立项） |
| 可成长的孔雀翎已沉淀整套自建底座：`Core\`（伤害类/成长曲线/限流/震屏/AdditiveLayer/调色板/键位/存档迁移/剧情库）+ UI 注册表式加页 + 文档驱动工作流 + 门禁 | 每一款新 mod 都将重写同一套底座——正是「工作室级框架」的候选素材 |
| 代理写码的正确姿势 = 读版本钉扎的权威资料（`TML_2026_07` 签名大革命已证明：网上旧教程/旧文档会直接给错签名） | 需要一份**版本化、结构化、代理可检索**的领域知识库，而不是散落的书签 |
| 用户 2026-09-03 拍板（附录 A）：知识库 = 版本化结构化 + 代理检索（先行）；框架 = 完整内容/事件/网络框架 | 本文档同时给出两工作包的总体设计，M0 拍板即完成 |

**非目标（红线，全文生效）**：不做独立 loader；不把 tML 已有的事件/注册能力复制成套娃层；不搬运灾厄等专有源码资产（合规 R8）；知识库/框架不阻塞孔雀翎既有开发节奏。

## 二、统一分层（先定语言，避免各说各话）

| 层 | 内容 | 生命周期 |
|---|---|---|
| **领域知识库**（`知识库\`，新顶层目录） | Terraria/tML 通用知识：Hook 签名、ModPlayer 专档、内容类型参考、原版数据表、渲染/网络/本地化、迁移史 | 版本钉扎；随 tML 大版本刷新；**与具体 mod 解耦，跨项目复用** |
| **框架**（独立 git，暂定代号 **PlumeCore / 翎核**，命名待 D） | 库模组 dll + 工程模板 + 契约文档：内容注册表 / 事件与服务 / 网络协议 / 存档迁移 / 横切件 | semver；tML 大版本 = major+1（D28） |
| **内容 mod**（可成长的孔雀翎等） | 具体玩法/内容；引用框架与知识库 | 各自 git |
| （对照）`写法\` | 孔雀翎**本项目**的剧本（现状/决策/交接） | 随项目 |
| （对照）tModLoader | 平台层（loader + Hook 分发 + 注册） | Re-Logic + tML 团队 |

一句话分工：**`写法\`= 本项目剧本；`知识库\`= 通用领域知识；框架 = 代码资产；内容 mod = 消费者。**

## 四、工作包 A：版本化结构化知识库（M1 先行）

### A1 目录骨架（`知识库\`，与 `mod本体\`、`写法\` 平级）

```
知识库\
  00_总索引.md            # 使用说明 + 版本钉扎 + 更新纪律 + 检索协议说明
  version-pin.md          # Terraria 版本 / TML_2026_07 / tML 源码 commit 快照 / 本库刷新日期
  01_平台概念\            # tML 架构：Mod / ModSystem / 内容类注册 / Global\* / 加载顺序 / 客户端-服务器模型
  02_内容类型参考\        # 每类一档：Item / Projectile / NPC / Tile / Wall / Buff / Player / World / UI
      ModPlayer.md        # ← 用户点名重点：存档键/迁移、每钩子签名与触发点、双端语义
  03_Hook目录\            # 每类一张表 + 自动生成：hook / 签名 / 触发时机 / 频率 / 覆盖要点 / 版本
      ModItem.md ModPlayer.md ModNPC.md ModSystem.md GlobalItem.md GlobalNPC.md ...
  04_原版数据表\          # wiki.gg 清洗：武器/NPC/Boss 数值、AI 列表、配方链、ID 段分配（M4 校准曲线用）
  05_配方与合成\ 06_网络与存档\ 07_渲染与特效\ 08_本地化\ 09_跨模组(Call)\
  10_工具链与构建\        # tML.targets / 打包 / tModPorter / 门禁移植 / 版本迁移史
  11_示例库\              # 精选 ExampleMod 范式 + 自家范式（附合规署名）
  12_迁移史\              # PortingNotes_1.4.5 / MigrationGuide_1.4.5 摘要 + 自家踩坑（热重载崩溃、无 Item 签名…）
  索引\ HOOK_INDEX.json   # 结构化索引（检索协议见 A4）
  _tools\ ingest-*.ps1    # 采集/同步/扫描脚本（D24）
```

### A2 来源与合规（D25）

| 源 | 装什么 | 合规动作 |
|---|---|---|
| tML 官方仓库（本地 clone，钉扎 commit） | `*Loader.cs` 调用点、内容类虚方法、ExampleMod、MigrationGuide/PortingNotes | MIT 可复用；反编译原版部分见 TERMS_OF_USE（本地参考 OK） |
| tML 官方 Wiki（`git clone ...tModLoader.wiki.git` 全量离线） | 开发者指南、Hook 文档 | 笔记化 + 出处引用（Wiki 协议≠代码协议） |
| Terraria wiki.gg | 原版数值/配方数据 | CC BY-NC-SA：本地自用可；导出需标注；不用于商用发布 |
| 生态模组源码 | 机制研读笔记（沿用现有三级署名制） | CalamityModPublic=参考级署名 / CWR=MIT / 社区开源 |
| 自产语料（最高价值） | 本仓 git 历史（`git log -p` 过滤 .cs）+ 设计文档 + 门禁通过代码 | 零合规问题；未来微调唯一可靠数据源 |

### A3 自动化工具（D24）

1. **`hook-scan.ps1`**：输入 = 钉扎版 tML 源码路径；扫描 `*Loader.cs` 中对内容类钩子的调用点 + 内容类虚方法声明 → 输出每类一张 `markdown` 表 + `索引\HOOK_INDEX.json`。**禁止手抄签名**（TML_2026_07 无 Item 参数时代，网上资料大多是旧的）。
2. **`ingest-wiki.ps1`**：clone/拉取 tML wiki 与官方仓库镜像；`ingest-wiki-gg.ps1`（数据表抓取清洗，标注版本与出处）。
3. **`version-pin` 纪律**：每次刷新必须改 `version-pin.md`；索引条目带 source 字段指向钉扎 commit。

### A4 检索契约（代理怎么用这份库）

- 代理入口 = `00_总索引.md`（地图 + 查表顺序 + 免责声明：以钉扎版本为准）。
- `HOOK_INDEX.json` 条目字段：`{ hook, declaringType, signature, trigger, frequency, whenToOverride, sourceVersion, notes }`。
- 铁律：**写码前先查 03_Hook目录/02_内容类型参考 对应页**；**签名以本库为准，不以记忆或旧教程为准**；发现出入 → 修库条目并记入 12_迁移史。

### A5 内容优先级

| 优先级 | 内容 | 理由 |
|---|---|---|
| P0 | Hook 目录 + ModPlayer 专档 + 内容类型参考骨架 + version-pin + 总索引 | 用户点名项；写码最高频命中 |
| P0 | 原版数据表（武器/NPC/Boss 数值、配方链） | 孔雀翎 M4 数值校准现成要用 |
| P1 | 渲染/特效、网络与存档、本地化、跨模组 | 孔雀翎网络 TODO（msgType=2）与渲染铁律直接受益 |
| P2 | UI 注册、工具链、迁移史全集、示例库 | 长期价值 |

### A6 质量与门禁

每条内容 = 清单：来源 ✅ 许可 ✅ 版本 ✅ 署名 ✅（外部内容）示例可编译（自家示例必须过编译）。门禁扩展（建议加 `-Mode KbAudit` 或独立 `知识库-Kb-Gate.ps1`）：条目数下限 / version-pin 存在且最新 / Hook 表非空 / 引用文件路径存在。

## 五、工作包 B：完整内容/事件/网络框架（目标形态）

### B1 总体分层

```
内容 mod（孔雀翎 / 未来 mod）
   │  csproj <Reference> + build.txt dependencies
   ▼
框架 API 面（PlumeCore 占位）—— 给内容 mod 的稳定编程接口
   ├─ 内容注册表：域注册（内容族注册/依赖顺序/自动 ID，杜绝硬编码 ID）
   ├─ 事件与服务：tML hook → 类型化服务/委托（带优先级与权重覆盖点）
   ├─ 网络协议：msgType 高段位分配 + 序列化辅助 + 服务器权威模板（MP 权威同步直接受益）
   ├─ 存档：玩家/世界数据容器 + 版本化迁移链（孔雀翎 v2 迁移经验泛化）
   └─ 横切件：调色板服务 / 粒子限流 / AdditiveLayer / 震屏 / 键位注册 / 本地化双轨 / UI 注册表
   │
   ▼
tModLoader（loader + Hook 分发 + 注册）→ Terraria
```

### B2 内核 API 草案（v1 范围 vs 后置，v1 内核对孔雀翎现有代码零破坏）

| 内核 | v1 范围（先做） | 后置 |
|---|---|---|
| 内容注册表 | 域注册表基类 + 内容族注册顺序 + 注册名/键命名规范 | 运行时动态注册、跨框架内容互操作 |
| 事件与服务 | 生命周期服务（`OnWorldLoad/OnEnter`…）、伤害解析服务（`IDamageResolver`，含伤害类继承权重默认表 + 覆盖点——念类 25% 继承经验） | 通用事件总线（若确实需要，先论证不套娃 tML） |
| 网络 | msgType 分配器（高段位 + 冲突检测）、序列化辅助、客户端请求→服务器校验模板 | 自动状态同步框架 |
| 存档 | 玩家/世界数据基类 + 版本号 + 迁移链（v2 迁移补偿范式） | 自动迁移代码生成 |
| 横切件 | 从孔雀翎 Core 提炼（见 B3） | — |

### B3 从孔雀翎提炼判定表（基于 `代码结构地图.md` 快照逐文件）

| 文件 | 判定 | 理由 |
|---|---|---|
| Core\EffectLimiterSystem.cs / ScreenShakeSystem.cs / AdditiveLayer.cs / MalachiteKeybinds.cs / MalachitePalette.cs | **入框架（直接）** | 纯基础设施，与玩法无关 |
| Core\TalentModel.cs / WillowGrowth.cs | **入框架（接口化）** | Evaluator + CurveProvider 通用；数值归内容 |
| Core\MindDamageClass.cs | **入框架（权重表 + 覆盖点）** | 跨 mod 伤害类组合是 Terraria 特有复杂度，锁死规则必打架 |
| Core\MalachiteProgress.cs + Players\MalachitePlayer.cs 存档 v2 段 | **入框架（存档基类 + 迁移链）** | 框架最值钱部分 |
| Core\MalachiteMelee.cs / Projectiles\* / UI 冻结区 / 对话文案 | **留内容层，只暴露钩子** | 内容不是框架 |
| World\MalachiteWorld.cs（掉落/发点） | 留内容；Boss 击杀表结构入框架 | 事件语义 vs 内容规则分离 |

### B4 反模式与边界红线

1. **不复制 tML 已有能力**（事件分发/注册 tML 原生有）；框架只做「工作室级一致性 + 跨自己多 mod 的契约」。
2. **机制件可插拔**：默认权重 + 覆盖点，不锁死规则。
3. **依赖地狱治理 = 版本纪律**：D28 semver；每 tML 大版本一次 breaking 发布 + 迁移指南；框架仓内放「已依赖框架的 mod 清单」。
4. **第一款消费者验证后再扩张**（D27）：内核 v1 必须在真实 mod 上跑通，禁止空转造框架。

### B5 工程布局与依赖协议

```
框架蓝本\            # 起草期（工作区），稳定后拆独立 git（D23）
  Framework\         # 库模组工程：PlumeCore.csproj → PlumeCore.dll → tML References 目录
  Template\          # 新 mod 工程模板：csproj + tML.targets + 目录骨架 + 通用门禁 + 文档模板
  Docs\              # 契约文档族（B6）
```

内容 mod 引用（骨架，同现有 tModLoader.targets 模式）：
```xml
<ItemGroup>
  <Reference Include="PlumeCore">
    <HintPath>E:\Steam\steamapps\common\tModLoader\References\PlumeCore.dll</HintPath>
  </Reference>
</ItemGroup>
```
```text
# build.txt
dependencies = PlumeCore@0.1
```
